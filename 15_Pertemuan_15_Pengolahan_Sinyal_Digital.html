📘 Visi Outcome-Based Education (OBE)

  • Puncak dari pembelajaran sarjana bukan sekadar menghafal rumus atau mengerjakan soal ujian tertulis di kertas, melainkan kemampuan MENERAPKAN ilmu untuk menyelesaikan masalah nyata di masyarakat dan industri (Project-Based Learning / PjBL).
  • Setiap kelompok mahasiswa wajib menghasilkan prototipe perangkat lunak DSP fungsional yang dapat didemonstrasikan secara langsung (live demo).
  • Fokus Proyek: Kejelasan masalah, legalitas data, ketepatan metode DSP, baseline pembanding yang adil, validasi metrik kuantitatif, dan keterbatasan sistem.

🚀 Struktur Standar Proyek Rekayasa

  • 1. Problem Definition: Masalah apa yang diselesaikan? Siapa pengguna sasaran?
  • 2. Data Integrity: Dari mana data diperoleh? Apa lisensi hak ciptanya?
  • 3. DSP Methodology: Metode pemfilteran dan analisis apa yang dipilih? Mengapa?
  • 4. Baseline Comparison: Dibandingkan dengan apa? (Sinyal mentah vs Filter Moving Average vs Filter FIR/IIR Terdesain).
  • 5. Quantitative Metrics: Berapa Delta SNR? Berapa penurunan noise? Berapa akurasi deteksi?

Metodologi Eksperimen Rekayasa & Baseline Pembanding

Slide 4 / 13

📌 1. Pemilihan Baseline Pembanding

  • Proyek rekayasa tidak boleh mengklaim 'solusi kami bagus' tanpa pembanding!
  • Baseline Wajib: Bandingkan algoritma Anda dengan minimal satu metode standar sederhana (misal Moving Average sederhana atau Raw Unprocessed Signal).
  • Buktikan secara matematis mengapa metode Anda lebih unggul!

📌 2. Parameter Tuning & Ablation Study

  • Ujilah pengaruh perubahan parameter desain terhadap kinerja sistem.
  • Contoh: Apa yang terjadi jika cutoff digeser 100 Hz? Apa dampak menaikkan orde filter dari 4 menjadi 8? Bagaimana pengaruh perubahan window Hamming vs Blackman?
  • Dokumentasikan dalam tabel eksperimen.

📌 3. Metrik Evaluasi Terukur

  • Evaluasi tidak boleh hanya berdasar asumsi perasaan ('suara terdengar lebih enak').
  • Wajib menyertakan angka metrik kuantitatif terukur: Delta SNR (dB), Mean Squared Error (MSE), Spectral Centroid Shift, atau Waktu Eksekusi (ms).

Implementasi Python: Template Logging Metrik Proyek

Slide 8 / 13

📖 Framework Evaluasi Proyek Komparatif

  • Script template profesional untuk menguji sinyal pada beberapa metode filter secara bersamaan.
  • Menghitung metrik SNR masukan vs keluaran dan persentase reduksi error secara otomatis.
  • Mengekspor tabel hasil evaluasi dalam format terstruktur yang siap disalin ke laporan proyek.
Python Implementation (NumPy / SciPy) 
import numpy as np

def calculate_snr(clean_ref, noisy_or_filtered):
    noise = clean_ref - noisy_or_filtered
    power_signal = np.mean(clean_ref ** 2)
    power_noise = np.mean(noise ** 2)
    if power_noise < 1e-12: return float('inf')
    return 10.0 * np.log10(power_signal / power_noise)

def evaluate_dsp_methods(clean_ref, raw_noisy, methods_dict):
    snr_input = calculate_snr(clean_ref, raw_noisy)
    print(f'=== HASIL EVALUASI METRIK PROYEK ===')
    print(f'Baseline Input SNR : {snr_input:.2f} dB\n')
    
    results = []
    for name, filtered_sig in methods_dict.items():
        snr_out = calculate_snr(clean_ref, filtered_sig)
        delta_snr = snr_out - snr_input
        mse = np.mean((clean_ref - filtered_sig) ** 2)
        results.append((name, snr_out, delta_snr, mse))
        print(f'Metode: {name:<20} | SNR Out: {snr_out:6.2f} dB | Delta SNR: {delta_snr:+5.2f} dB | MSE: {mse:.6f}')
    return results
